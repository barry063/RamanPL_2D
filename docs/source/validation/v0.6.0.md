# v0.6.0 Validation Report

This page summarises the validation evidence for the v0.6.0 stable interpretable-analysis
milestone. All numbers are reproducible by running
`benchmarks/validation_v0.6.0_vs_v0.5.0.py` from the repository root.

---

## Scope

Four synthetic cubes were tested:

| Cube | Shape | Description |
|------|-------|-------------|
| `small_3x4` | (3, 4, 150) | Primary parity-check and runtime-reference cube |
| `extended_15x15` | (15, 15, 150) | Large-scale fit throughput |
| `tall_axis_10x12` | (10, 12, 500) | Extended spectral axis |
| `hard_3x4` | (3, 4, 150) | Overlapping peaks (500 and 530 cm⁻¹), SNR≈1.7, `maxfev=50` |

`small_3x4` and `tall_axis_10x12` were run across a 2×2 grid of fit-kwarg variants:
`warm_start ∈ {False, True}` × `n_starts ∈ {1, 4}`. `extended_15x15` was run with
`n_starts=1` only (the `n_starts=4` variant is skipped for this cube to reduce
wall-clock; scale coverage is the validation goal, not multistart exhaustion).
The hard cube was run twice: once with `use_peak_proposals=False` and once with
`use_peak_proposals=True`.

---

## Method

- **Synthetic cubes:** deterministic Lorentzian/Gaussian peaks with additive Gaussian
  noise. No real WDF data is used, ensuring hardware-independent reproducibility.
- **Seeds:** `random_state=42` for all fits; `numpy.random.default_rng(42)` for cube
  construction (standard cubes), `numpy.random.default_rng(99)` for the hard cube.
- **v0.5.0 reference snapshot:** generated by `benchmarks/_step0_snapshot.py`.
  Reference files committed to `benchmarks/results/v0.5.0_baseline/`.
- **Parity criterion:** per-peak column values compared numerically with
  `rtol=1e-3, atol=1e-3` (same criterion as
  `tests/test_export_fit_map_qa_columns.py::test_wide_format_existing_columns_unchanged`).
  This tolerates LAPACK/scipy floating-point differences across builds while catching
  genuine algorithmic regressions.

## Findings

Numbers are taken from `benchmarks/results/v0.6.0_validation_summary.json`.

### Fit-quality parity

| Field | Value |
|-------|-------|
| v0.5.0 reference SHA256 | `ee894af8490a2d7c19ea94c6ae13a94dbc1ac3e3243ae21de43d7cee192b1d82` |
| Per-peak column parity | **PASS** |

Per-peak column values on the `small_3x4` cube (x, y, peak position, FWHM, peak height,
peak height normalised, amplitude, scale factor) match the v0.5.0 reference within
`rtol=1e-3, atol=1e-3`. This confirms that no fitting algorithm changes were introduced
between v0.5.0 and v0.6.0.

### Runtime comparison

| Metric | v0.5.0 baseline | v0.6.0 | Ratio |
|--------|----------------|--------|-------|
| `n_curve_fit_calls` (`small_3x4`, `n_starts=1`) | 12 | 12 | 1.00× |
| Wall-clock runtime (`small_3x4`, `n_starts=1`) | 0.827 s (median) | ~0.79 s | ~0.96× |

`n_curve_fit_calls` is the hardware-independent primary metric; wall-clock timing is
advisory (±20% across runs due to scipy iteration state and warm-start behaviour).
No increase in curve-fit calls indicates no algorithmic regression.

### Failure-mode comparison

| Condition | Failed pixels (hard_3x4, `maxfev=50`) |
|-----------|--------------------------------------|
| `use_peak_proposals=False` | 0 |
| `use_peak_proposals=True` | 0 |

Both runs converged on all 12 pixels of the hard cube with `maxfev=50`. The peak-proposal
fallback was not triggered (primary fitting succeeded without it). This is consistent with
the hard cube's peaks being within the fitting bounds and the 50-evaluation budget being
sufficient for these particular parameters.

## Scientific position

Deterministic Lorentzian / pseudo-Voigt least-squares fitting remains the final
authority for all reported peak parameters. Machine-learning components (v0.5.4 `[ml]`
extra) operate only on fitted descriptors, not on raw spectra. Supervised classification
(e.g. layer-number labels) remains deferred to v0.7.x, conditional on the availability
of curated, labelled, multi-instrument datasets.

This position is unchanged from the v0.5.3 scientific note in `README.md`.
