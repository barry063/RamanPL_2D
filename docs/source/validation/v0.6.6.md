# Validation report — v0.6.6

**Build type:** Consolidation pause — API freeze, validation, and documentation  
**Date:** 2026-06-02  
**Harness:** `benchmarks/validation_v0.6.6_vs_v0.6.0.py`  
**Outputs:** `benchmarks/results/v0.6.6_validation.csv`, `benchmarks/results/v0.6.6_validation_summary.json`

---

## Purpose

v0.6.6 adds no new fitting algorithms, preprocessing algorithms, peak models,
or export schemas. Its purpose is to freeze and validate the additive public
surface introduced in v0.6.1–v0.6.5, and to document the resulting contracts.

---

## Synthetic dataset

All gates use the standard `small_3x4` benchmark cube:

- Shape: `(3, 4, 150)` — 12 pixels, 150 spectral points
- Spectral axis: 200–1800 cm⁻¹
- Single Si peak at 520 cm⁻¹ (FWHM ≈ 15 cm⁻¹), Gaussian noise σ = 0.05
- Deterministic RNG seed 42; background subtraction disabled

This is the same cube used in the `validation_v0.6.0_vs_v0.5.0.py` harness.

## Gate results

All gates passed. Summary JSON:


### Gate 1 — Fit output parity

`fit_spectra()` with omitted new keywords produces a SHA256-identical export to
`fit_spectra(show_progress=True, n_jobs=1, cluster_seeds=False)`. The three new
defaults introduced in v0.6.1–v0.6.5 are confirmed to have no effect on fitted
values when set to their defaults.

**Result:** PASS — SHA256 match on `small_3x4` / `n_starts=1`.

### Gate 2 — Export schema stability

The export SHA256 for `small_3x4 / warm_start=False / n_starts=1` matches the
v0.6.0 reference (`ee894af8…`). Feature-table QA columns
(`rmse`, `ok`, `n_starts`, `n_params_at_bounds`) are all present.

**Result:** PASS.

### Gate 3 — Call-count sanity

`n_curve_fit_calls = 12` for `small_3x4 / n_starts=1`, matching the v0.6.0
reference of 12 (within the ±25% tolerance window). Wall-clock timing is
advisory and not a release gate.

**Result:** PASS — 12 calls, ref = 12, tolerance ±25%.

### Gate 4 — Parallel safety

- `n_jobs=2 / warm_start=False`: completed without error.
- `n_jobs=2 / warm_start=True / row_reset=False`: raised `ValueError` as
  expected (unsafe warm-start state propagation is blocked, not silent).

**Result:** PASS (both sub-gates).

### Gate 5 — Cluster-seed boundary

- `cluster_seeds=False` parity: SHA256-identical export to default call.
- `cluster_seeds=True, n_jobs=2`: raised as expected — cluster seeding is
  serial-only.

**Result:** PASS (both sub-gates).

### Gate 6 — Autotune non-mutation

- `autotune_baseline(seed_coord=(0,0), plot=False)` returned a result without
  mutating `preprocessing`.
- `apply_choice(result.winner)` mutated `preprocessing` as expected.

**Result:** PASS (both sub-gates).

### Gate 7 — Batch progress default

`fit_spectra_batch` has `show_progress=True` as the frozen default (confirmed
Gate 0.2). Omitting `show_progress` preserves batch fit behaviour.

**Result:** PASS.

---

## Known limitations

- `cluster_seeds=True` is **serial-only** (`n_jobs=1` required). Two-phase
  parallel cluster dispatch is deferred to a later release.
- On the homogeneous `small_3x4` synthetic cube, `cluster_seeds=True` does not
  reduce `n_curve_fit_calls` compared to the default initialisation. The
  measured benefit depends on multi-domain data with spectrally distinct regions.
  This limitation was recorded in `closeout_v0.6.5.md` and is not addressed in
  v0.6.6.
- No new fitting algorithms, preprocessing algorithms, peak models, or export
  schemas are introduced in v0.6.6.
